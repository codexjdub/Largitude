BUILD INSTRUCTIONS
There is no build step. The add-on is the extension/ folder of the source repository as it is: every file in it is hand-written, and nothing is minified, transpiled or generated.

WHY THE CODE WORKS THIS WAY
content.js runs in each frame's content-script world, not the page's own. It looks at what is under the pointer and shows the full-size version of the image or video there in a popup: an element in a shadow root, shown as a manual popover so it sits above the page. Its styles are set through element.style, not a stylesheet, so a page's Content-Security-Policy can't block them.

helpers.js holds the functions with no side effects (parsing srcset, placing the popup and the like), kept apart to be unit-tested in Node. The files in sites/ hold what the add-on knows about particular sites, one file each, loaded as content scripts between helpers.js and content.js. Each works out, from an image's address on its site (preview.redd.it on Reddit, for example), the address of the original upload (i.redd.it), which is tried first; some also recognize the images of one post (a Reddit gallery, an X or Bluesky post's images). sites/image-services.js does the same for services many sites use (WordPress, Next.js, Cloudinary, imgix, Google), taking the requested size out of the address. Two lead to another host: Jetpack's i0.wp.com copies and Next.js's /_next/image?url=…, to the image they name.

Videos: a link to a video file, a video the page plays from a file (not a blob: stream, but for Reddit's player the MP4 files it lists), or an address a site rule turns into one, plays in the popup in a <video> the content script makes, muted and looping. Closing the popup removes the video's address and calls load(), which stops its download.

In a gallery, the arrow keys and the wheel move through its images; the wheel listener exists only while one is open.

background.js gives each frame its settings, such as whether its site is on the user's list of sites to leave alone (by the tab's page as well as the frame's address). They're in storage.sync, which Firefox Sync carries to the user's other computers, each site an item of its own. The toolbar button adds the tab's site to the list or takes it off.

The downloads permission: when the user presses S with the popup open, background.js saves the image or video the popup shows with downloads.download, under a file name taken from its address. A download from a private window is private. O opens the same file in a new tab, with tabs.create. For C, content.js draws the popup's image into a canvas and puts it on the clipboard as a PNG with navigator.clipboard.write, during the keypress; where the canvas can't be read, background.js fetches the file, uncached.

The add-on loads only the images and videos the page itself refers to, or larger versions of them at addresses worked out from those. It collects no data and sends nothing anywhere.
