BUILD INSTRUCTIONS
There is no build step. The add-on is the extension/ folder of the source repository as it is: every file in it is hand-written, and nothing is minified, transpiled or generated.

WHY THE CODE WORKS THIS WAY
content.js runs in each frame's content-script world, not the page's own. It looks at what is under the pointer and shows the full-size version of the image or video there in a popup: an element in a shadow root, shown as a manual popover so it sits above the page. Its styles are set through element.style, not a stylesheet, so a page's Content-Security-Policy can't block them.

helpers.js holds the functions with no side effects (parsing srcset, placing the popup, matching the list of sites to leave alone), kept in a file of their own so they can be unit-tested in Node. The files in sites/ hold what the add-on knows about particular sites, one file each, loaded as content scripts between helpers.js and content.js. Each works out, from an image's address on its site (preview.redd.it on Reddit, pbs.twimg.com on X, i.imgur.com), the address of the original upload on the same service (i.redd.it; pbs.twimg.com with name=orig, or video.twimg.com for the MP4 of an X GIF; the .mp4 behind an Imgur .gifv), which is tried first, and recognizes the images of one post (a Reddit gallery, an X post's photos).

Videos: a link to a video file, a video the page plays from a file (not a blob: stream), or an address a site rule turns into one, plays in the popup in a <video> element the content script makes, muted and looping. M unmutes it and Space pauses it, only while the popup is open. Closing the popup removes the video's address and calls load(), which stops its download.

When the image is one of a post's several (a Reddit gallery, an X post's photos), the arrow keys and the mouse wheel move through them. The wheel listener is added only while such a popup is open, and removed when it closes.

background.js gives each frame its settings: whether its site is on the user's list of sites to leave alone (going by the tab's page as well as the frame's own address), and which way the mouse wheel moves through a gallery.

The downloads permission: when the user presses S with the popup open, background.js saves the image or video the popup shows with downloads.download, under a file name taken from its address. Firefox's own setting decides whether to ask where to save; a download from a private window is made private.

The add-on loads only the images and videos the page itself refers to, or larger versions of them from the same services. It collects no data and sends nothing anywhere.
