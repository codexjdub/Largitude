# Developing Largitude

How Largitude works, and how to work on it. What it does and how to install it are in the [README](README.md), which is written for the people who use it.

## Trying it

There is no build step: `extension/` is the extension, exactly as it goes to Firefox Add-ons. To try it, open `about:debugging#/runtime/this-firefox`, click **Load Temporary Add-on…**, and choose `extension/manifest.json`. Firefox removes it when it restarts. `npx web-ext@10 build --source-dir extension` packages it as a zip in `web-ext-artifacts/`, which **Load Temporary Add-on…** takes too.

## Checks

```
npm run lint
npm test
```

`npm run lint` checks the extension with Mozilla's add-on checker (`web-ext lint`, fetched by `npx` on first use). `npm test` runs the unit tests of `extension/helpers.js`, `settings.js`, `background.js`, the settings page and the site rules with Node's own test runner (Node 20+), with stand-ins for Firefox's APIs; nothing needs installing.

The test page has one card for each kind of image Largitude should show, or leave alone. Run `npm run serve`, open http://127.0.0.1:8766/test/test-page.html with the extension installed, and click **Run checks**: it hovers each card with synthetic mouse events and lists what the popup showed, then checks opening and closing. With `?standalone` added to the address, the page loads the content script itself, with a stand-in for the extension APIs, so it also works in other browsers (closed shadow roots excepted), and it also checks the motion and the timing: the keys lighting up, the slide, the change of shape and the bump, the copy flying off on S, the next popup opening sooner, loading during the wait, the long image panning, and ← → going on past a gallery to the page's next image. In a page that isn't shown, such as a background tab, browsers hold back animations and frames, so the checks finish animations before measuring (`settled`), but a few that depend on timing can fail there that pass in a tab you're looking at.

On every push, a GitHub Action, **Tests**, runs the add-on checker and the unit tests.

## Site rules

What Largitude knows about particular sites is in `extension/sites/`, one file per site, each added with `addSite` (from `helpers.js`). `image-services.js` is the exception: it holds the rules for image services many sites use (WordPress, Next.js, Cloudinary, imgix, Google), whatever site they're on. A site's `larger` rules are pairs of a regular expression and its replacement: when the expression matches an image's address, the address with the replacement put in is a larger version, tried first. Its `gallery` function, if it has one, finds the images of the post an image is in. Six more are optional: `standIn` recognizes an image a site sends in place of a file it doesn't have (YouTube's gray 120×90 still), which the popup skips like a failed load, `leaveAlone` leaves a site's own images to it (YouTube's thumbnails on YouTube, which play a preview), `video` finds files of a video the site streams (the MP4s Reddit's player lists in `packaged-media-json`), which the popup plays instead, `original` finds an image's original where the page lists it away from the image (Google Images' results, in its scripts), `fileName` names a saved file whose address names it poorly (Reddit's videos and YouTube's stills, named after their size; Bluesky's images, whose type comes after an @), and `pageImages` lists, in order, the images ← → go on through from one post to the next (X's photos and GIFs), which also tells the popup it may scroll for more at the end of the list. A new site's file goes in the manifest's content scripts, between `helpers.js` and `content.js` (a test checks), and its rules get tests in `test/sites.test.mjs`.

## Releasing

Bump `version` in `extension/manifest.json` for each release. The release's notes start with a `## What's new` heading; the list under it, up to any `## Updating` section, becomes the version's release notes on Firefox Add-ons, as plain text.

Publishing a GitHub release runs another GitHub Action, **Firefox Add-ons**, which submits that version of the extension to Firefox Add-ons with the notes for Mozilla's reviewers (`amo/reviewer-notes.txt`) and the release's "What's new", and sets the listing's description to `amo/description.txt` as it is in that release. The new description shows on Firefox Add-ons as soon as the release is submitted, before Mozilla has approved the version. It needs two repository secrets, `AMO_JWT_ISSUER` and `AMO_JWT_SECRET`, from an [API key on Firefox Add-ons](https://addons.mozilla.org/developers/addon/api/key/). A failed submission can be retried from the Actions tab with **Run workflow** and the release's tag.

The listing's other fields, the ones that stay the same from one version to the next (its website), are in `amo/listing.json`. A change to it on `main` runs **Firefox Add-ons listing**, which sends it to Firefox Add-ons straight away, with the same secrets.

The listing's screenshots are the PNGs in `amo/screenshots`, in the order and with the captions of `screenshots.json`. `npm run screenshots` takes them again (`make.mjs`): Largitude's content scripts on made-up pages (`scenes.html`), with pictures drawn for them (`art.mjs`), in Chrome without a window, moved over with real mouse moves and key presses; it needs Google Chrome or Chromium (`CHROME=<path>` names one). A change to them on `main` runs **Firefox Add-ons screenshots**, which puts them on the listing in place of the ones there, with the same secrets. Firefox Add-ons allows an author 3 changes a minute, 10 an hour and 24 a day, releases included, so it changes only what differs (a screenshot already there has the same pixels as its file, though not the same bytes) and waits when it's told to.

The [README](README.md) and the listing's description (`amo/description.txt`) are what users read: keep them in step with what Largitude does.

## How it works

The details are in the code's comments. This is a map of where to find them, with the reasons the code doesn't make obvious. `helpers.js` holds the parts with no side effects, unit-tested in Node; `content.js` does the rest, in each frame; `background.js` gives each frame its settings and saves files; `settings.js` keeps the settings, for it and the settings page.

- **Finding the image** (`findImage`, `imageOf`). Everything under the pointer, topmost first, through shadow roots, closed ones included, which Firefox lets extensions see. Transparent overlays are looked through; text, an opaque background or a video stops the search. A `blob:` video is a stream that can't be played anywhere else, so it's left alone, unless a site's `video` knows files of it (`streamedVideoOf`), checked for the poster shown before it plays too; the popup then starts where the page's video is.
- **The full-size address** (`sourcesOf`, `withRules`). An original a site's `original` finds (`listedOriginal`), a link to an image or video file, then the largest `srcset` candidate, then the image shown, each preceded by any larger version the site rules know (`fullSizeUrls`). An address that fails moves on to the next; once the popup shows it, it stays if the rest doesn't come, with a note.
- **Opening** (`open`, `load`, `present`, `fetchMedia`). Loading starts halfway through the wait (`load`), so the file is often in when the popup is due (`open`); whichever comes second shows it (`present`). After a popup, an image of about the same size (`similarSize`) hovered within `WARM_FOR` opens after `WARM_DELAY` instead of the whole wait (`warm`); scrolling the page ends that. The size always comes from loading the file afresh: an image the browser picked from a `srcset` reports the size it's shown at as its own. The popup opens as soon as the size is known, at its final size, with the thumbnail standing in, blurred, until the image has loaded, and only if it's at least 20% bigger than the image on the page. For a moment a corner gives the size and how much bigger it is than the thumbnail (`sizeFactor`, `sizeLabel`); I shows that and more over the popup (`toggleInfo`), the file's size coming from what the page loaded (`bytesOf`).
- **Placing** (`placePopup`). Beside the pointer, on the side that shows the image largest, or over the whole window when no side shows it well, so where the pointer happens to be never decides whether there's a popup. A long, narrow image opens wide enough to read where that's much wider than the whole image fitted to the window (`readableSize`, `boxFor`), and the pointer's place down the thumbnail picks the part shown (`panTall`, `panOffset`), with a bar for where it is (`tallBar`).
- **Galleries** (each site's `gallery`, `go`, `onWheel`). The wheel moves one image per gesture, so a trackpad's momentum counts once. The image before slides out as the next slides in (`slideOut`, `slideIn`), while the popup takes the next one's shape: a reshape adds transitions on the host's box to `placeHost`'s, taken off again once it's done. Past either end, or with no gallery, ← → go on to the page's next image (`pageStep`): from a site's `pageImages`, or else the page's `<img>` elements of about the same size (`pageImages`, `neighbor`), scrolled into view, and at the end of a site's list `loadMore` scrolls for more. While it steps, `steering` keeps that scrolling, and the mouse event Firefox sends after it, from closing the popup; a real move of the mouse, the wheel or another key ends it. With no image further on, the popup bumps (`bump`). It's only listened to while a gallery is open: a listener that can stop scrolling makes Firefox wait on it at every turn of the wheel.
- **Videos** (`videoSourcesOf`, `makeVideo`). What a page's `<video>` plays loads as a video whatever its address, since many sites leave off the file extension. Outside a gallery and a site's list of page images (X's GIFs), ← → move it back or on (`seekBy`, `arrowsMove`).
- **Keys** (the `keydown` listener, `isTyping`; `openInTab`, `copyImage` and `copyAddress`, and `toggleActualSize` with `lookAround` for Z, `turn` for R, `flip` for F, `toggleKeys` for ?). Only while the popup is open, and they don't reach the page. Keys typed in a text field are left alone, following the focus into web components, whose keys seem to come from the component itself. C draws the popup's own image into a canvas (`pngOf`), which Firefox lets an extension that may read every site read, and hands the clipboard a promise of the PNG, since Firefox allows the clipboard only during the keypress. Where the canvas can't be read, the background script fetches the file (`imageFile`), out of the cache, which a private window's image would otherwise land in. Firefox gives the clipboard to https pages only, so on http pages the line of keys leaves C out, and Shift+C copies through the Copy command (`copyAsCommand`). F mirrors before turning (`viewTransform`), so after R it reverses the turns (`turnsOnceFlipped`) to mirror what's on the screen. A line under the popup lists a few keys for what it shows (`showHint`), unless the setting is off; `placePopup` keeps room for it. A key pressed lights up there and in the panel of keys (`flashKey`).
- **Saving** (`save`, in content.js and background.js). The background script downloads the file, since content scripts can't. A `data:` or `blob:` image is the page's own, so the content script reads it (`pageFile`) and sends it, and the background script saves or opens it from an address of its own. The name comes from the address (`fileNameFor`, and a site's `fileName`); one with no type, such as Google's `photo=s0`, gets the type the server gives (`typeAt`). Firefox refuses a name it would have to change, so the characters it would change are changed first, and should it refuse one anyway, the file is saved under the name Firefox gives it. The content script remembers what it saved (`savedNames`), so S on the same address says so and needs pressing again within 3 seconds to save a copy. Once saved, a copy of what's shown, drawn into a canvas, flies to the top right of the window, where Firefox's Downloads button is (`flyToDownloads`).
- **Isolation** (`createHost`). The popup is a `popover`, in the top layer above the page's own dialogs, with its styles set on its elements, which a page's content security policy can't block. It doesn't clip what's in it, so the line of keys can sit under it and the panel of keys can be larger than it; the image and the notes are in an inner box that does. It fades in and out (`FADE`, at once with reduced motion); fading out, it keeps its image until it's gone (`finishHiding`), and a popup opening meanwhile cuts the fade short.
- **Motion** (`placeHost`, `startAt`, `settleFrom`, `MOTION`). The popup's own `transform` moves it, a CSS transition taking it from where it starts to where it's placed: grown from the thumbnail (`growTransform`) when it opens, shrunk back into it when it closes, turned from where it was for R (`turnTransform`) and turned over for F. Its styles are set `!important` against the page's, and a transition still applies to those, where an animation wouldn't; inside the shadow root, where the page can't reach, the slide, the bump, the keys lighting up and the copy flying off on S are animations (`animate`). Where the popup goes is worked out from where it's placed (`hostBox`), not where it's seen, which is somewhere else until a transition ends. With reduced motion, `MOTION` and `FADE` are 0 and nothing moves.
- **Settings** (`settingsFor`; `storedItems` and `optionsFrom` in `settings.js`). Decided for each frame, going by the tab's page too, so a frame embedded on a site to leave alone is left alone. Kept in `storage.sync`, each site to leave alone an item of its own, since Firefox Sync merges item by item: sites added on two computers are both kept. A save writes only new or moved sites and takes off only those gone from the list, so two saves at once don't undo each other, and one that Firefox's limits on synced storage turn down writes nothing (`overLimit`). The background script reads the settings once for every frame until they change (`loadOptions`); frames that hear of a change ask for a fresh read (`freshOptions`), which they may hear of before it does. The settings page leaves the list alone while it's being edited, and saves the edit on top of what changed meanwhile (`rebasedList`). Settings kept locally before 0.8.0 move over once (`moveToSync`), and are read where they were until then.
- **Toolbar button** (`browser.action.onClicked`, `showState`, in background.js; `listWithSite` and `listWithoutSite` in helpers.js). It edits the sites to leave alone, and its badge and icon (`icon-off.svg`, grayed) follow the list for each tab.
