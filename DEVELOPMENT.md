# Developing Largitude

How Largitude works, and how to work on it. What it does and how to install it are in the [README](README.md), which is written for the people who use it.

## Trying it

There is no build step: `extension/` is the extension, exactly as it goes to Firefox Add-ons. To try it, open `about:debugging#/runtime/this-firefox`, click **Load Temporary Add-on…**, and choose `extension/manifest.json`. Firefox removes it when it restarts. `npx web-ext@10 build --source-dir extension` packages it as a zip in `web-ext-artifacts/`, which **Load Temporary Add-on…** takes too.

## Checks

```
npm run lint
npm test
```

`npm run lint` checks the extension with Mozilla's add-on checker (`web-ext lint`, fetched by `npx` on first use). `npm test` runs the unit tests of `extension/helpers.js` and the site rules with Node's own test runner (Node 20+); nothing needs installing.

The test page has one card for each kind of image Largitude should show, or leave alone. Run `npm run serve`, open http://127.0.0.1:8766/test/test-page.html with the extension installed, and click **Run checks**: it hovers each card with synthetic mouse events and lists what the popup showed, then checks opening and closing. With `?standalone` added to the address, the page loads the content script itself, with a stand-in for the extension APIs, so it also works in other browsers (closed shadow roots excepted).

On every push, a GitHub Action, **Tests**, runs the add-on checker and the unit tests.

## Site rules

What Largitude knows about particular sites is in `extension/sites/`, one file per site, each added with `addSite` (from `helpers.js`). A site's `larger` rules are pairs of a regular expression and its replacement: when the expression matches an image's address, the address with the replacement put in is a larger version, tried first. Its `gallery` function, if it has one, finds the images of the post an image is in. A new site's file goes in the manifest's content scripts, between `helpers.js` and `content.js` (a test checks), and its rules get tests in `test/sites.test.mjs`.

## Releasing

Bump `version` in `extension/manifest.json` for each release. The release's notes start with a `## What's new` heading; the list under it, up to any `## Updating` section, becomes the version's release notes on Firefox Add-ons, as plain text.

Publishing a GitHub release runs another GitHub Action, **Firefox Add-ons**, which submits that version of the extension to Firefox Add-ons with the notes for Mozilla's reviewers (`amo/reviewer-notes.txt`) and the release's "What's new", and sets the listing's description to `amo/description.txt` as it is in that release. The new description shows on Firefox Add-ons as soon as the release is submitted, before Mozilla has approved the version. It needs two repository secrets, `AMO_JWT_ISSUER` and `AMO_JWT_SECRET`, from an [API key on Firefox Add-ons](https://addons.mozilla.org/developers/addon/api/key/). A failed submission can be retried from the Actions tab with **Run workflow** and the release's tag.

The [README](README.md) and the listing's description (`amo/description.txt`) are what users read: keep them in step with what Largitude does.

## How it works

- **Finding the image.** When the pointer moves, Largitude looks at everything under it (`elementsFromPoint`), topmost first, including inside shadow roots: closed ones too, which Firefox lets extensions see. It looks through transparent overlays, which many sites lay over their images, and stops at text or at an element with a background color of its own, since that hides what's under it. The first `<img>`, CSS background image or `<video>` playing a file it finds, 24 px or more each way, is the one. A video the page streams (a `blob:` address, put together piece by piece, as YouTube's and most players are) can't be played anywhere else, and it hides what's under it, so the search stops there. An image that ignores the mouse (`pointer-events: none`) is found inside the element over it. Failing all that, a link under the pointer counts if it leads to an image or video file, or to one the site rules know.
- **The full-size address.** For each image, Largitude tries in turn: a link around it to an image or video file, the largest candidate in its `srcset` (and those of the `<source>` elements around it in a `<picture>`), and what the page shows. Lazy-loading pages keep the last two in `data-lazy-srcset` and `data-lazy-src` until the image comes into view. Before each address comes any larger version the site rules know of. An address that fails to load moves it on to the next.
- **Site rules.** Reddit shows copies at most 1080 px wide (`preview.redd.it`); the original upload is on `i.redd.it` under the copy's id, which newer copies put after words from the post's title (`some-title-v0-<id>.png`). X picks a photo's size with `name=` (`small`, `large`, …), and `name=orig` is the original; profile pictures drop `_normal` or `_400x400`, and banners go to `1500x500`. An X GIF is an MP4 on `video.twimg.com`, named after its still (`tweet_video_thumb/<id>`). Imgur's `.gifv` addresses are pages that play the `.mp4` of the same name.
- **Opening.** The pointer rests on the image for 300 ms first. The full image starts loading then, and the popup opens as soon as its size is known, at its final size, with the page's thumbnail standing in until the full image has arrived. A spinner shows if that takes more than 150 ms. The size always comes from loading the file, even when it's the page's own copy (from the cache then): an image the browser picked from a `srcset` reports the size it's shown at, not its own. The popup doesn't open when it wouldn't be at least 20% wider or taller than the image on the page.
- **Placing.** The image is fitted, never past its own size, into whichever side of the pointer shows it largest, next to the pointer. It covers the window instead when every side would show it at less than two thirds of what the whole window allows, or when only the whole window shows it clearly bigger than the page does, so where the pointer happens to be never decides whether there's a popup. The popup lets the mouse through, so it never gets in the way.
- **Galleries.** When the image is one of a post's several, the popup shows where it is ("2 / 5"), and ← → or the mouse wheel move through the rest, with the images on either side loading in advance. Reddit galleries are a `<gallery-carousel>` with every slide in the page as an `<li>`, the ones not in view yet included. X posts link each photo to `…/status/<post>/photo/<n>` within the post's `<article>`; a quoted post's photos have another post's number and are left out. The wheel moves through a gallery the way it scrolls the page: the turn or swipe that would scroll the page down shows the next image, whichever way the computer's scrolling goes, and **Reverse the mouse wheel in galleries** in the settings turns that around. The wheel moves one image per gesture: a gesture ends after 150 ms without wheel movement, so a trackpad swipe and its momentum count once. Past either end, the next gesture scrolls the page as usual. While a gallery is open, the keys and the wheel don't reach the page. The wheel is only listened to while a gallery is open, since a listener that can stop scrolling makes the browser wait on it for every turn of the wheel.
- **Videos.** An address ending in `.mp4`, `.webm`, `.m4v` or `.ogv` loads as a video, muted and looping, as a GIF would be, and so does whatever a `<video>` on the page plays, whatever its address looks like: many sites serve videos at addresses without a file extension. Its size comes with its metadata, so the popup opens at its final size as for an image, with the page's poster or thumbnail as the popup video's own poster until the first frame. A video from the page starts where the page's is. A thin bar along the bottom shows how far it has played, moved by the video's own progress events. M turns the sound on or off (or says there's none, which Firefox can tell), and Space pauses and plays; neither reaches the page. Keys typed into a text field are left alone, including a field inside a web component, which the page sees as the component itself. If Firefox is set to block all autoplay on the site, the popup says so, and Space plays it. Closing the popup stops the download, and a gallery doesn't load videos in advance.
- **Saving.** With a popup open, S saves the image or video it shows, as the full-size file it came from. The background script downloads it (with the `downloads` permission), and Firefox's own setting decides whether to ask where; a private window's download stays private. The file is named after the last part of the address, with the type added when the address gives it elsewhere, as X's `?format=jpg` does. A note in the popup says "Saved", "Not saved" (the save dialog was canceled) or "Couldn't save".
- **Closing.** Moving off the image, leaving the window, or scrolling the page (or a box the image is in) closes the popup; another box on the page scrolling, such as a chat, leaves it open. A click or Escape closes it too, and it stays closed until the pointer leaves the image. Escape then doesn't reach the page, which might otherwise close a dialog of its own.
- **Isolation.** The popup lives in a shadow root on a `popover="manual"` element, so it sits in the browser's top layer, above everything the page shows, its own dialogs included. Its styles are set on its elements rather than in a stylesheet, which a page's content security policy can't block, and `!important` on the outer element beats the page's stylesheets. The content script runs in its own world, out of the page's reach.
- **Settings.** The settings page keeps a list of sites to leave alone, and the wheel's direction in galleries. The wheel's setting is stored under a new name since 0.4.1, where the usual direction changed, so a choice made under 0.3.0's meaning isn't read the wrong way round. A change applies at once, on pages already open too. The background script decides for each frame, going by the tab's page as well as the frame's own address, so a frame embedded on a site in the list is left alone too.

## Limits

- A popup for an image inside a frame stays inside that frame, so a small frame leaves no room for one.
- Site rules cover Reddit, X and Imgur's GIFVs so far. Elsewhere only the addresses the page itself gives are tried; rules for YouTube, Reddit video and common image CDNs come next.
- Galleries are recognized on Reddit and X only.
- Videos a page streams can't be shown, since there's no file to play elsewhere: YouTube's, X's videos (as opposed to its GIFs), Reddit's, and most news sites' players.
